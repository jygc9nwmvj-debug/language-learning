# Evidence Discipline v0.1

Use three labels throughout curriculum, UX and learning-engine design:

**EVIDENCE** — directly supported principle, with scope/limitations.  
**DERIVED** — design rule inferred from evidence + domain constraints.  
**HYPOTHESIS** — concrete implementation/product choice to test.

Examples:
- Spacing improves delayed retention: EVIDENCE.
- Increase spacing after stable delayed retrieval: DERIVED.
- Review 好 again after exactly 24 hours: HYPOTHESIS.

- Scaffolding/fading principles: EVIDENCE.
- Hide Pinyin as independent retrieval stabilizes: DERIVED.
- Hide it after two correct attempts: HYPOTHESIS.

- Interleaving can improve discrimination/transfer, but can be too difficult during initial acquisition in some tasks/populations: EVIDENCE with limitation.
- Use short focused acquisition blocks followed by increasing interleaving: DERIVED.
- Lesson 1's exact exercise order: HYPOTHESIS.

Every important hypothesis should have an observable test where practical.

Never write “research says” when the research only supports a broader principle than the actual product decision.
