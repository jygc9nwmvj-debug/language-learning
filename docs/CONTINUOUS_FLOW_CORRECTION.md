# Continuous-flow pilot correction — 2026-09-29

Baseline: main `bc0e5c6`, verified against deployed worker `mandarin-v01-27e4824089b2bb0c` at https://language-learning-abk.pages.dev/. No Lab/Research branch was used.

The D scheduler appends a `closure` sentinel to a bounded plan. LessonRunner exposed it as “Runde abgeschlossen”, offering both Weiterlernen and Weiter, with a further completion/reflection screen. Build E added a proactive Meaningful Stop heuristic at that same boundary. Repeated real-use reports say this interrupts motivated learning subjectively too early. These thresholds were unvalidated product hypotheses. Remove the intervention, without claiming that every future stopping recommendation is bad or proposing another optimal duration.

LessonRunner now checks existing Paper Recall eligibility at the boundary and otherwise immediately composes the next plan through the unchanged Continuous Learning scheduler. Paper completion or skipping also continues automatically. There is no stop prompt, round-completion screen or completion-only reflection UI. Loading and failed-save retry remain possible; neither represents a prescribed stopping point. The header's “Für jetzt aufhören” returns home; Weiterlernen retains existing resume/replanning behavior.

Internal plan limits, retry placement, dosing, consolidation intervals, relation updates, script, persistent records and resume windows remain unchanged. A single transaction completes the previous batch and saves the next batch and linked lifecycle events. Failure rolls back that transition and allows retry. A successfully saved Paper Recall result remains saved even if the following transition fails. No schema migration, reset, new stop heuristic, duration limit or historical rewrite.

F-light retains per-batch session IDs, per-visit active-time checkpoints, task presentation/retrieval intervals and existing `session_pause` / `session_resume` / `session_start` events. Automatic transitions use existing `session_end` and `learning_continue` types with `reason: batch_transition` and reciprocal next/previous session IDs. The report's session count remains a count of recorded internal IDs; it must not be interpreted as a count of voluntary learner stops. Continuous motivated learning may span multiple such IDs. No invisible closure is logged as a presented learning task. Historical `meaningful_stop_offered`, `session_stop_accepted`, `voluntary_continue_after_stop` and reflection records remain readable/exportable; production no longer emits the three stop-intervention events. The historical heuristic and report handling remain available for old evidence.

Screenless Recall and Paper Recall selection, cooldowns, reveal persistence and self-report semantics are untouched. Paper results do not change individual handwriting relations. All unrelated content, writing, audio and assessment behavior remain unchanged.

Verification: full existing automated suite once, 84/84 passed; production build/content validation passed (44 canonical words, 36 items, 131 tasks, 76 audio references). Ten focused browser checks passed across Chrome and WebKit: real task completion and two successive batches; absence of stop/completion screens; persisted state and historical events; voluntary exit, reload and resume; transactional rollback/retry; existing Screenless and Paper eligibility, reveal and result semantics; active-time, assistance and retrieval-interval evidence. No broad browser, A1/A2, writing acceptance or UI audit.

OPEN: Can a future non-intrusive stopping opportunity help without fragmenting motivation, imposing arbitrary duration or pretending to know an individual's optimum? Observe natural session lengths, active time, voluntary stopping, retention and repeated learner reports before revisiting. No implementation now.
